# Project decision register

`format.ts` exports the data types and pure parse, serialize, add, supersede and query operations. `store.ts` exports `DecisionRegister.open(repo)` with `read`, `write`, `add` and `supersede`. `why.ts` and `decide.ts` each export `register(program)` for the CLI. `source.ts` checks evidence paths. No harness or service is involved.

The register is `docs/decisions.md`, a Markdown table with these columns in order:

```
| ID | Date | Decision | Made by | Status | Source | Class | Reversibility | Why | Alternatives | Depends on | Supersedes |
```

It has a standard Markdown separator row and one physical row per decision. A heading and blank lines are optional. New registers use `# Decisions`. IDs are positive safe integers written `D1`, `D2`, etc.; additions use the largest existing ID plus one. Dates are real calendar dates in `YYYY-MM-DD` form. Maker values are `fabricio`, `accepted-default`, `jarvis`, `inferred`, and `unconfirmed-default`; classes are `Mechanical`, `Taste`, and `Challenge`. Reversibility is `reversible`, `easy`, `moderate`, `hard`, or `irreversible`. Choice, source and rationale must be nonblank. Sources are normalized repo-relative paths with an optional nonempty `#anchor`. Absolute paths, dot segments, backslashes and control characters are refused by the input schema. Every write checks existence and real-path containment under the repository. Source symlinks staying within the repo are allowed; symlinked `docs/` or `decisions.md` are refused on reads and writes. Alternatives and dependencies are JSON arrays of strings, including empty arrays when none apply.

Status is `active` or `superseded-by D2 on 2026-10-24: "Fabricio's reason"` (the reason is a JSON string). The replacement's `Supersedes` column links back with `D1`; unrelated entries use `-`. Both links, their dates, and increasing IDs are checked. All other fields survive supersession unchanged. Taste dependencies are retained for the future targeted replan; this module does not implement reporting or replanning.

Cells escape backslashes as `\\`, pipes as `\|`, newlines as `\n`, carriage returns as `\r`, tabs as `\t`, and boundary spaces as `\s`. These escapes also apply inside JSON cells. Unknown escapes are errors. Parsing followed by serialization preserves the original text exactly, including line endings, padding and final newlines. Updates preserve untouched rows. Malformed input reports the physical line number.

The storage layer takes an exclusive `docs/.decisions.lock` before reading and allocating IDs. It writes and fsyncs a unique sibling temporary file, closes it, then renames it and fsyncs the directory. The lock records pid, host and ISO time; busy errors show those fields. Reading lock metadata never follows a symlink. Failed writes or renames leave the old file intact and clean up the temporary file. Writes refuse missing entries, rewritten choices or history, nonsequential new IDs, and stale snapshots. Superseding any firm, inferred, unconfirmed-default or Challenge entry requires a replacement made by `fabricio`, including through generic `write`. Every supersession requires a reason; Jarvis can otherwise revise its own Mechanical/Taste calls. All programmatic writers must use this module's lock. An abandoned lock requires operator inspection and removal; it is never automatically reclaimed. Atomic replacement coordinates module callers; hand edits do not participate in the lock.

`checkConflicts(activeDecisions, statedChoices, requestDate)` is pure: it returns `settled` instructions and intake `questions`; it never writes the register. Intake must explicitly map each stated choice to an active decision ID and classify its author and explicit/implied intent. Missing choices retain existing decisions. Fabricio's explicit change requires his reason; without one the result is a question. Jarvis may revisit its own Mechanical/Taste calls only with an explicit choice and a note. Inferred, unconfirmed-default and Challenge calls require confirmation. Unresolved questions default to `keep`, with `switch` and `feature-only` alternatives. Callers apply settled changes or intake answers through `supersede`, retaining their date, reason and provenance; a feature-only answer belongs in the feature's spec rather than replacing the global decision. `firmness(entry)` exposes the ownership policy and confirmation requirement.

`why <query> [--repo <dir>] [--history]` searches literal, case-insensitive keywords in choices, reasons, sources, alternatives and dependencies, or exact numeric/D-prefixed IDs. A numeric query falls back to keyword search when that ID does not exist. Default results include only active entries. History includes matching entries plus their connected predecessors and successors. Missing registers and no matches print a message and succeed without creating files; malformed registers fail with a line-numbered error.

`decide "<choice>" --by user|default-accepted|default-unconfirmed|jarvis --class mechanical|taste|challenge --source evidence.md#anchor --why "<rationale>" [--repo <dir>]` is the only CLI writer. It uses today's UTC date and prints only the canonical new ID (`D1`, etc.). The CLI maps makers and classes exactly as decisions 83 and 85 specify; `inferred` is a format value rather than a CLI maker. `--reversibility` defaults to `reversible`; `--alternatives` and `--depends-on` accept JSON arrays of nonblank strings or `-` for none (the default). `--supersedes D1 --reason "<reason>"` links a replacement; a missing or orphan `--reason` is refused. Invalid writes print an error and exit nonzero without replacing the register.

`mutations.json` contains integrator-ready mutation definitions, exercised against this lane's tests. The integrator can append them to the shared mutation runner; only the six lane test files were used for local validation.

### Explicit user answers

`--by user` requires `--answer <answerSeq>:<questionId>`. The sequence identifies the intake answer intent in this repository's derived project ledger. The CLI verifies the ledger, the explicit session answer and its recorded user provenance, then requires the decision text to match that answer exactly. The reference is retained in Why. Phone defaults, timeout defaults, free-text phone notes and unrelated statements cannot supply this authority. Superseding a decision additionally requires its D ID in the recorded question or answer.

There is no TTY or environment-variable exemption. A terminal caller can use the same recorded-answer path; a session can create a pseudo-terminal, so TTY presence cannot establish who authored a decision. Unrecorded corrections stay in the intake record until an answer can be recorded.

`checkSpecRegister(repo, source)` checks decision citations and declared header ranges against the current register. `checkSpecRepository(repo)` wraps the existing history checker and applies those current-register checks to the latest spec only. Semantic contradictions, answered open questions and evidence for state labels remain the fresh reader's responsibility.
