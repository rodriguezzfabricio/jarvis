| 1 | high | Concurrent broker requests execute one approved payload more than once | **Fixed:** the ledger gained `transact`, which reads the verified entries and appends under the writer lock in one step. The broker takes its whole decision there, synchronously: duplicate, pending, rejected, or claim. An executing intent without a receipt blocks any new execution (`in_progress`, exit 2) until it settles; only a definite `failed` receipt permits a retry. Intents record the broker's pid, and `reconcile()` settles only intents whose broker is dead, so a second broker can't mark a live execution unknown. The receipt is written in a transaction too, one per execution. **Tests:** concurrent `handle()` calls on one broker with a barrier adapter; two brokers on one ledger, with `reconcile()` during the execution; four broker *processes* racing on one approved payload (one adapter call); three concurrent requests over the socket. **Mutations:** "broker starts a second execution while one runs", "reconcile settles live executions". |
| 2 | high | Encoded configuration credentials pass the snapshot scan | **Fixed:** every quoted literal with escapes is decoded (JSON `\/` and `\uXXXX`, YAML `\x`, `\U`, JS `\u{…}`) and scanned as an extra view, and percent-encoded URL syntax is decoded too. Configuration files (JSON, YAML, TOML, INI, properties, `.npmrc` and similar) are also inspected by field name: a credential-named field (`password`, `*_token`, `clientSecret`, `api_key`, `*_master_key`, …) with a literal value is refused. Empty values, references (`${X}`, `${{ secrets.X }}`, `{{ x }}`), placeholders and non-string scalars are inert; a reference's default (`${X:-value}`) is judged like the value. `.netrc` and `.pgpass` need review. **Tests:** snapshot-level refusals for slash-escaped, Unicode-escaped, `\x`-escaped and percent-encoded URLs, an escaped GitHub token, and literal password, `clientSecret`, `bot_token`, `api_key`, `MEILI_MASTER_KEY`, JSONC, INI, `.npmrc`, `.netrc` and compose-default cases; plus a snapshot that must pass with inert fields (`author`, `auth: true`, `${API_KEY}`, `${{ secrets.GITHUB_TOKEN }}`). Tasks 01 and 02 now list the reviewed `docker-compose.yml` (documented dev defaults) and three job-board fixtures (public `job_token` ids) in `allowSecretsIn`; both snapshots succeed. **Mutations:** "snapshot ignores format encoding", "snapshot ignores credential fields", "reference defaults are trusted". |
| 3 | high | Candidate code can exit successfully before protected assertions run | **Fixed (decision 76):** a check has two phases in separate sandboxes. `command` runs the candidate and writes observations to `$JARVIS_OUT`; `verify` holds the assertions, runs no candidate code, can't read the checkout, reads only the checks and a copy of the observations made after phase 1, and must end with `JARVIS-CHECK-COMPLETE <nonce>`, where the nonce is written after phase 1 in a folder phase 1 can't read. A pass needs both phases to exit 0 on their own and the completion line. Observations are hashed into the evidence. **Tests:** a candidate that exits 0 during "import" (sourced) before anything is observed fails, while the honest candidate passes and a wrong one fails; a verify phase that stops early with 0, prints the wrong nonce, prints after the line, or exits 1 fails; candidate output that plants a guessed completion line fails; a check without a verify phase is an error; observation edits are detected; on macOS, the verify phase can't read the checkout or the live output folder and the candidate can't see the verify folder. **Mutations:** "gate ignores the completion line", "gate ignores the candidate phase's exit", "verify phase can read the checkout", "candidate can read the verify folder". |
| 4 | medium | A crash during stale-lock reclamation permanently blocks future appends | **Fixed (cheap):** markers are created like locks (atomic, holding "pid nonce"), and a marker whose owner died is reclaimed the same way one level down, so no crash leaves a blocking file. The lock holder sweeps markers for lock instances that no longer exist. **Tests:** dead markers at depths 1–3 recover; a live reclaimer's marker is still respected; a fault test SIGKILLs a reclaimer at `reclaim-claimed`, then a normal writer appends and every acknowledged entry is intact. **Mutations:** "lock reclaimed without a marker", "a dead reclaimer's marker blocks forever".
