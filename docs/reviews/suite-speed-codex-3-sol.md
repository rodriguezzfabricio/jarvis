## Strongest case against the change, written before deciding

Before deciding, the strongest case against this change is that it can break the required default full-suite command and contaminate the mutation gate with infrastructure failures.

The new helper at tests/unit/helpers/native-git-test.ts:12 imposes a 10-second limit on an external Node process that starts many native Git commands. The fresh exact-head full-suite run actually exhausted this limit in the new execFileSync comparison. pnpm test returned 1 (initial host log, lines 1267–1317), despite install and typecheck succeeding. A targeted green run would not disprove a full-suite contention failure.

The helper converts child.error into a Vitest assertion failure at line 14. scripts/mutation-classify.mjs rejects messages containing “test timed out” or “timed out in Nms”, but not a child-process ETIMEDOUT serialized inside an AssertionError. Therefore an unchanged native execution path that is merely slow could look like a clean mutation catch if the control happened to pass. This is a static concern pending a separate controlled execution of the classifier; it is not yet an execution-proven finding.

Other credible risks need evidence: copied .git templates might share mutable state or change native branch/config semantics; the ACL stub removes incidental real adapter coverage from setup flows; pooled snapshot workers might misassociate responses or fail to propagate setup exceptions; moving safety cases to new files might change mutation selection or omit tests.
