| 1 | high | Candidate code can fabricate observations and earn a passing gate | **Fixed (decision 76, revised):** the runner is the driver. A check is a list of cases plus a verify phase. The runner runs each case in the candidate sandbox and records that process's own stdout, stderr and exit code in the evidence folder, which no sandbox can write; nothing the candidate writes to disk is an observation. The candidate sandbox can read the checkout and `checks/fixtures/`, not the expectations, the verify folder or the observations. `verify` runs with no candidate code and no checkout, over a copy of the recorded observations, and must end with the nonce written after every case ended. A case that times out fails the gate. **Tests:** a candidate that writes the expected observation into every reachable observation path (the verify copy, `$JARVIS_OUT`, the evidence folder) and then exits during import fails, as do an early exit and a wrong answer, while the honest candidate passes; a killed case is recorded as `signal`; a timed-out case fails even when verify completes; several cases are recorded separately; on macOS the candidate can't read the runner folder, the expectations or the verify folder (it can read fixtures), and verify can't read the checkout or the candidate's home. **Mutations:** "candidate can read the expectations", "candidate can read the verify folder", "verify phase can read the checkout", "gate ignores the completion line", "gate ignores case timeouts", "gate records a signal as exit 0". |
| 2 | high | Configuration credential inspection still fails open | **Fixed:** JSON, JSONC (comments and trailing commas removed outside strings), JSON5-style flow and YAML (block and folded scalars, flow mappings, anchors and merges, multiple documents) and TOML are parsed into typed values and walked. A string under a credential name is a credential unless it's empty, a reference or a placeholder; digits are no longer exempt, and a number of 4+ digits under a credential name counts too. plist keys, XML elements (including CDATA) and XML attributes are read by structure; INI-like files line by line. A structured file that doesn't parse but names credential fields is refused. Every text view (UTF-8, UTF-16) and the percent-decoded text is inspected. `fieldName` now splits acronyms (`APIToken` → `api_token`). **Tests:** snapshot-level refusals for each reported case (block scalar, flow mapping, compact JSONC, plist, quoted numeric password) plus folded scalars, anchors, bare numeric PINs, TOML inline tables, XML elements, attributes and CDATA, unparseable YAML and UTF-16 JSON; the inert snapshot also keeps a commented `tsconfig.json`, a Maven `${env.X}` reference and numeric limits. **Mutations:** "config files read line by line", "numeric passwords exempt", "unparseable configs pass", "snapshot ignores credential fields". |
