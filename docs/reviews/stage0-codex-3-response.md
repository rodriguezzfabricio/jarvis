# Response to stage 0 review 3 (Codex)

Oct 23, 2026. Reviewed revision `c5a7997`; fixes are in the next commit. Each finding was reproduced or checked in code first, and each fix has a regression test and a mutation in `scripts/mutation-check.mjs`.

| # | Severity | Finding | Response |
|---|---|---|---|
| 1 | high | The placeholder rule exempts real passwords | **Fixed:** no length or punctuation exemptions. Only complete template forms (`%s`, `<name>`, `{name}`, `${NAME}`, `$NAME`, `***`, `xxx`) or whole-value placeholder words count, after percent-decoding. **Tests:** Codex's three reproductions (`N7q4%40…`, `Pa$$w0rd!x9`, `8k2Z`) plus `u:p` are all flagged. Ambiguous fixtures go through `allowSecretsIn`: FreeHire's `test_engines.py` (`u:p@1.2.3.4`) is now listed there by review, in jarvis-evals. |
| 2 | high | Binary private keys pass the scan | **Fixed:** every file of 64 KiB or less that parses as a DER private key (PKCS#8, PKCS#1, SEC1) is refused, and so are credential containers (`.p12`, `.pfx`, `.jks`, `.keystore`, `.kdbx`, `.ppk`, `.gpg`, binary `.key`/`.der`, …) unless reviewed. **Test:** a generated RSA PKCS#8 DER key under a neutral name (`signing.bin`) is refused, as is a `.p12`. |
| 2b | — | No size-boundary test | **Added:** files at and one byte over the limit (the limit is a test seam). |
| 3 | medium | The mutation classifier accepts infrastructure failures | **Fixed:** `scripts/mutation-classify.mjs` checks the process signal and spawn error, file-level errors, *identical test identities* with the control run, and timeouts. "Caught" needs at least one assertion failure. **Tests:** 8 cases (timeouts, SIGKILL, spawn error, missing report, collection error, unhandled error, changed identities, non-assertion failure). |
| 4 | medium | No bounded kill after a capture failure | **Fixed:** one idempotent shutdown sends SIGTERM to the session's *process group*, then SIGKILL after a grace period. Writing this test exposed a related gap: a killed shell's grandchild kept the output pipes open. Sessions now run in their own process group, and leftovers are cleaned when the session ends. **Test:** a child that ignores SIGTERM is gone within the grace period. |
| 5 | medium | Spawn failures count as completed baselines | **Fixed:** a spawn failure rejects with `SessionStartError`, and its diagnostic is written to the stderr evidence file. A run with no `init` event is `started: false` and stops the chain explicitly; it's never counted. **Tests:** session and scheduler paths. |
| 6 | medium | The scheduler waits or "stops" after the final run | **Fixed:** a high-usage wait is applied just before the next dispatch, never after the last run. **Tests:** a final task with its reset inside and beyond the cap returns at once, completed, with no stop. |
